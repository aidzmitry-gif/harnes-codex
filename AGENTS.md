# Операционный контракт агента

## Цель

Доставлять проверяемые изменения с минимальным риском, стоимостью и количеством переделок. Автономность означает самостоятельное исследование и проверку, а не самостоятельное расширение задачи.

- Не крути цикл на уверенности — крути его на уликах: опирайся на файлы, тесты, расчёты, наблюдаемое поведение и первичные источники.
- Отделяй подтверждённые факты от выводов и допущений.

## Обязательный цикл

Перед любой правкой выполнить последовательность из `docs/ENGINEERING_LOOP.md`:

1. **Ориентация:** прочитать локальные инструкции, найти точки входа, тесты, конфигурацию и текущее состояние git.
2. **Контракт:** записать в work item проблему, результат, границы, инварианты, критерии приёмки и способ проверки.
3. **Карта воздействия:** назвать затронутые компоненты, потребителей, данные, безопасность, миграции и откат. Если неизвестна точка изменения — продолжать исследование, а не редактирование.
4. **Preflight:** запустить `scripts/Invoke-HarnessGate.ps1 -Stage prechange`.
5. **Минимальный срез:** изменить наименьший слой, который способен доказать гипотезу. Не совмещать рефакторинг, форматирование и новую функциональность.
6. **Проверка:** сначала адресная, затем быстрая, затем полная — согласно риску.
7. **Рецензия результата:** прочитать собственный diff как пользователь, потребитель API и ревьюер безопасности.
8. **Передача:** сообщить результат, доказательства, ограничения и остаточные риски.

## Стоп-условия

## Лестница лени и code review

Перед реализацией остановиться на первой достаточной ступени: (1) не делать — YAGNI; (2) stdlib/возможность языка; (3) нативный примитив платформы; (4) уже установленная зависимость; (5) одна прямая строка; (6) минимальный работающий код. Удаление важнее добавления; не создавать абстракции, конфиги, фабрики и инфраструктуру «про запас».

Не упрощать валидацию на границах доверия, защиту от потери данных/денег, безопасность, права, приватность, доступность, транзакционность, конкурентность и явно запрошенное поведение. Намеренное ограничение помечать `ponytail:` только с измеримым порогом и путём апгрейда.

Code review выполнять двумя последовательными проходами: сначала корректность/контракты/безопасность/тесты, затем simplify-проход по лестнице лени. Упрощение не может отменять находки первого прохода. Полный канон: `.agents/skills/goal-runner/references/laziness-ladder.md`.

Остановиться и запросить направление, если:

- цель, владелец данных или ожидаемое поведение неоднозначны;
- изменение требует внешнего доступа, публикации, удаления данных, миграции либо секретов без явного разрешения;
- предположение о контракте нельзя проверить локальными доказательствами;
- предварительная проверка выявила несвязанную грязную рабочую копию, и нельзя безопасно изолировать свои файлы;
- проверка не проходит и причина не локализована после двух независимых диагностических попыток.

## Порядок проверки

| Риск | Минимум доказательств |
| --- | --- |
| Низкий: текст, изолированная UI-правка | линтер/сборка и ручная проверка целевого сценария |
| Средний: бизнес-логика, API, интеграция | целевой тест, быстрый набор, diff-review |
| Высокий: auth, платежи, данные, права, миграции | контрактные и интеграционные тесты, план отката, ручной security-review |

## Экономия без потери качества

- Начинать с `rg`, существующих тестов и конфигурации — не сканировать весь проект без необходимости.
- Формулировать одну проверяемую гипотезу на итерацию.
- Использовать существующие паттерны и зависимости, не добавлять инфраструктуру без необходимости.
- Сохранять краткие доказательства в work item, чтобы не повторять исследование.
- Не запускать тяжёлые проверки, пока не прошёл целевой тест; для высокого риска полный прогон обязателен.

## Безопасность

Никогда не печатать и не коммитить ключи, токены, реальные персональные данные или `.env`. Не выполнять деструктивные команды, миграции и внешние операции без явного разрешения. Новая поверхность ввода, авторизации, хранения данных или сетевого доступа требует отдельного пункта в карте воздействия.

Graphify запускается локально и не передаёт код проекта во внешние сервисы. Это не отменяет проверку того, какие именно команды и входные данные запускаются в проекте.
