# HRE-007 — маршрутизация моделей и честный отчёт задачи

## Цель и разрешение

Запрос пользователя 2026-09-06: основная реализация GPT-5.6 Luna xhigh,
сложные задачи GPT-6; показывать токены, неудачные попытки и процент выполнения.
Разрешены локальные изменения Harness и проверки. CRM, production, глобальная
конфигурация Codex, активные паспорта и массовая рассылка обновлений не меняются.

## Контракт и наблюдения

- Исходная ветка `codex/hre-004-update-watcher`, рабочее дерево чистое.
- Startup pointers: harness_metrics.py, goal_runner_validator.py,
  goal_orchestrator.py, .codex/agents, .agents/skills/goal-runner/SKILL.md.
- Graphify подтвердил связь планировщика с валидатором и метрик с benchmark;
  актуальность поведения проверена по коду, не по графу.
- Сейчас допускаются только terra/sol; фиксированные роли используют Terra/Sol.
- schema 1 хранит attempts и checksFailed, но не failedAttempts. Они не эквивалентны.
- Документация OpenAI и callable runtime подтверждают gpt-5.6-luna/xhigh и
  gpt-6-astra/high,xhigh. Выбор пользователя — политика, не доказательство экономии.

## Приёмка и карта воздействия

1. План переносит модель и effort до launch; старые паспорта совместимы,
   неподдерживаемые пары отклоняются. Новые роли: Luna xhigh worker/explorer,
   Astra high lead, Astra xhigh verifier. Права и cap неизменны.
2. Журнал читает старую schema 1 и новую schema 2 с явным failedAttempts.
   task-отчёт фильтрует chain, отклоняет двойной учёт runId, не выдаёт неполные
   токены/неудачи за полный итог. Процент = свежие принятые критерии / все критерии.
3. Skill и шаблоны требуют короткий отчёт с фактической моделью; отсутствующие
   usage считаются неизвестными. No-progress и approval gates сохранены.
4. Целевые тесты, prechange/postchange/release и skill validation проходят.

Риск средний: локальные форматы, планировщик, роли и installer; новых сетевых
вызовов, секретов, прав, зависимостей и production-изменений нет. Нижняя
достаточная ступень — существующие stdlib CLI и acceptance gate. Откат —
реверс только среза HRE-007, без очистки чужих файлов. Core manifest старого
опубликованного релиза не переиздаётся автоматически.

## Проверки и метрики

Baseline `hre007-before`, treatment `hre007-after`; синтетические тесты не являются
парой измерения экономии. Runtime token usage этого изменения недоступен: null.
Процент не оценивать по коду. Acceptance gate: `.harness/acceptance/hre-007.json`,
4 критерия (целевые тесты, полный release, валидация skill, correctness/simplify review).

## Реализовано и проверено локально

- Passport принимает точные новые model/effort, planner передаёт effort в launch.
  Legacy Terra/Sol остаются совместимы; модель не расширяет права запуска.
- Source role/config/installer обновлены; глобальная конфигурация не менялась.
  Junction пользовательского goal-runner указывает на этот source skill, но
  загруженные в текущую задачу фиксированные роли автоматически не переключаются.
- Новый read-only `harness_metrics.py task`, schema 2 с failedAttempts; старые
  schema-1 события читаются. Неизвестные/неполные итоги null; повтор runId запрещён.
- 57 целевых тестов PASS (1.218 s). Postchange PASS, полный Python suite 135 PASS
  (17.608 s), architecture и bootstrap PASS. Skill Creator quick_validate PASS.
- Проверены diff, отсутствие новых секретов/прав/сетевых вызовов, отдельный
  simplify-review: один расширенный CLI вместо новой подсистемы/зависимостей.
- Новый локальный manifest `2026.09.06-hre007.1` рассчитан по изменённым файлам;
  прежний release ID не переиспользован. Публикации/обновления других проектов нет.
- До итоговой приёмки наблюдались 4 неудачные проверки: prechange без доступа
  к временным каталогам; ошибочное ожидание теста CHAIN_AUTH; устаревший текстовый
  контракт Use Luna; временный каталог Windows в новом CLI-тесте. Причины устранены.
  Ожидаемый TDD-red и ошибки подготовки команд не считаются попытками приёмки.
- Финальная свежесть и фактические команды сохраняются самим acceptance gate;
  не заменять их этой записью. Экономия моделей не измерена; реальный usage токенов
  текущей задачи недоступен. Для текущего отчёта используется только измеренный
  финальный checkpoint, не придуманный исторический итог времени/токенов.
- В финальном цикле две captured-проверки release не прошли: вложенный Windows
  PowerShell не находил стандартный Get-FileHash. Прямой release PASS, 135 тестов
  (16.010 s), isolated installer PASS. В command критерия добавлен `$PSHOME/Modules`
  только в PSModulePath дочернего процесса; системные настройки не изменяются.
  Повторная приёмка обязательна. Оба неудачных checkpoint сохраняются в метриках.
