# Work item: context-handoff

## Цель

- Проблема: длинные задачи после сжатия сохраняют большой пользовательский и браузерный контекст; ручной переход в новую задачу не фиксирует единообразный handoff.
- Ожидаемый исход для пользователя: вызов `$context-handoff` формирует компактную каноническую запись состояния, создаёт чистую задачу в том же проекте только после явного подтверждения и предлагает архивировать старую задачу после проверки новой.
- Не входит в задачу: автоматический переход по проценту контекста, удаление истории, принудительная архивация, изменение продуктового механизма `/compact`, копирование полного transcript или изображений.

## Контракт и доказательства до правки

- Наблюдения: в harness пока нет навыков, hooks или команды handoff; рабочие карточки живут в `.harness/work/`; корень не является git-репозиторием; Codex предоставляет операции создания и архивации задач, но они требуют явного пользовательского намерения.
- Гипотеза: небольшой навык `context-handoff` с каноническим шаблоном и строгими стоп-условиями обеспечит повторяемый переход без переноса старой истории.
- Оракул: валидатор навыков принимает структуру; статическая проверка подтверждает обязательные этапы snapshot → подтверждение → новая задача → проверка → предложение архивации и запрещает fork/автоархивирование.
- Инварианты / совместимость: существующие AGENTS.md и локальные инструкции приоритетны; существующие журналы не перезаписываются целиком; секреты, изображения и полные логи не переносятся; без явного подтверждения новая задача и архивирование не выполняются.

## Карта воздействия

- Компоненты и потребители: новый навык harness; агент Codex; проекты, подключающие harness; канонический журнал конкретного проекта.
- Данные / миграции: только Markdown-снимок состояния; миграций нет.
- Безопасность / права / секреты: запрет включать секреты, персональные данные, `.env`, полные логи и browser snapshots; создание задачи и архивация являются отдельными подтверждаемыми действиями.
- Внешние зависимости: текущие инструменты Codex для работы с задачами; навык должен корректно деградировать до готового стартового prompt/deep link, если инструмент создания задач недоступен.
- Риск: средний — workflow способен создавать и архивировать задачи, поэтому нужны явные подтверждения и двухфазный переход.
- Откат: удалить каталог навыка и связанные упоминания/проверки; созданная новая задача остаётся видимой и не удаляется автоматически.
