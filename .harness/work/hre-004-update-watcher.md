# Work item: HRE-004 — автономный наблюдатель обновлений OpenAI

## Цель

- Проблема: `update_impact.py` надёжно классифицирует один подготовленный кандидат, но не хранит просмотренное состояние, не подавляет повторы и не формирует итог одного запуска для фоновой задачи.
- Ожидаемый исход для пользователя: запланированная задача без участия пользователя проверяет свежие официальные источники, передаёт только новые структурированные кандидаты локальному watcher, а затем сообщает либо о доказанно значимом изменении и следующей локальной проверке, либо «Значимых обновлений для Harness нет».
- Не входит в задачу: автоматическое изменение исходников, commit, push, PR, deploy, установка/обновление Codex или Graphify, исполнение текста источника, доступ к секретам, обход sandbox/approval.

## Контракт и доказательства до правки

- Наблюдения (файлы, тесты, логи): HRE-003 принят с 89 тестами; `update_impact.py classify` работает offline и не хранит состояние; официальный OpenAI Docs подтверждает фоновые Scheduled Tasks в локальном проекте и рекомендует минимальные разрешения; Graphify-граф не содержит нового `update_impact.py`, поэтому точка изменения подтверждена прямым чтением исходника и тестов.
- Гипотеза: один stdlib CLI над существующим `update_impact.classify` сможет атомарно учитывать новые кандидаты, не повторять прежние выводы и выдавать ограниченный детерминированный отчёт, пригодный для Scheduled Task.
- Оракул: два последовательных запуска на одном пакете дают сначала классификацию новых кандидатов, затем `no-meaningful-updates`; изменённый кандидат с прежним ID, невалидный пакет и переполнение состояния завершаются fail-closed без изменения state-файла.
- Инварианты / совместимость: схема кандидата HRE-003 и его пороги не меняются; facts/inferences/assumptions остаются раздельными; разрешены только точные официальные HTTPS-hosts; запись состояния происходит лишь после полной валидации пакета; `AGENTS.md` не меняется.

## Карта воздействия

- Компоненты и потребители: новый watcher CLI, `update_impact.py` как единственный классификатор, тесты, README/ADOPTION, архитектурная проверка, prompt запланированной задачи.
- Данные / миграции: локальный JSON state schema v1 с ID и SHA-256 кандидатов; миграция отсутствует; путь состояния передаётся явно и не должен коммититься.
- Безопасность / права / секреты: runtime-код не получает сетевых или shell-возможностей; Scheduled Task читает только официальные OpenAI Docs и не меняет проект; состояние не содержит содержимое страниц или секреты.
- Внешние зависимости: официальный веб-доступ Scheduled Task; локальный watcher использует только Python stdlib и существующий модуль.
- Риск: средний — фоновая сеть и долговременное состояние, но без автоматического применения изменений.
- Откат: остановить Scheduled Task и удалить новый CLI/документацию; state-файл независим от исходников и может быть сохранён для аудита.
