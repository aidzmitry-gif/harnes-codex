# GPT-6.1 Terra в Harness и ERP

Проверено по официальным источникам 28 октября 2026 года. Поддержка модели в
валидаторе и установка роли не доказывают качество её результата или экономию.

## Выбор и совместимость

Используйте точный ID `gpt-6.1-terra`. Прежний alias `terra` не переназначается.
Codex CLI требует версию 0.159.0 или новее; выбор остаётся явным:

```powershell
codex --model gpt-6.1-terra
```

В исполняемом паспорте укажите `model: "gpt-6.1-terra"` и явный
`reasoningEffort`. Текущий Codex host объявляет low/medium/high/xhigh/max/ultra;
валидатор отвергает отсутствующий effort, none, minimal и неизвестные значения.
Это профиль Codex, не спецификация API: Responses API отдельно поддерживает
none/low/medium/high/xhigh/max, а tool calling требует Responses. Ultra —
возможность данного Codex host; не передавайте его автоматически в API.
`gpt-6.1-sol` также принимается явно для сопоставимого сравнения; действующие
паспорта и defaults Luna/Sol/Astra не переключаются.

## Применение

`harness_goal_visual` — Terra/high/read-only: существующие экраны, снимки,
графики, сравнение документов и видимого поведения. Пакет задаёт страницу,
контрольные точки, размер окна, разрешённые действия и критерий приёмки.
Роль возвращает источник/маршрут, наблюдаемые состояния и неизвестное; не
изменяет записи, настройки, права и файлы, не отправляет сообщения.

В ERP Terra может найти несовпадение колонки, подписи, единицы, итога или
состояния формы. Скриншот не подтверждает свежесть остатков, бухгалтерскую
корректность или RBAC: проверяйте фактические данные и регрессии; финансовую,
security и production-приёмку оставляйте независимому проверяющему Astra.
Ограниченные исправления кода возможны только через явно разрешённую пишущую
роль/основного исполнителя, не через read-only visual.

Для нового низкорискового сравнения начните с medium и одинаковых входов;
существующий high визуальной роли сохраняется. Увеличивайте effort только при
наблюдаемой пользе. Перед сравнением задайте оракул, затем измерьте качество,
время с исправлениями и реальные tokens. Сравните Terra и Sol при одинаковом
effort; отсутствие runtime usage остаётся «нет данных».

## Установка и границы

Пятая роль устанавливается существующим Install-GoalRunner. Для уже управляемой
установки используйте `-RolesOnly`: preview через `-WhatIf`, затем применение;
config и cap сохраняются побайтно. Нужна новая сессия Codex; текущая не меняется
от редактирования исходников. Чужие/изменённые роли не перезаписываются.

Core переносится только существующим [маршрутом распространения](DISTRIBUTION.md)
в согласованный idle checkout. Новый receipt подтверждает файлы, не приёмку ERP.
Не ставьте пакет поверх активной грязной рабочей копии, не переносите AGENTS.md,
живую историю радара, секреты или профили и не запускайте deploy.
